## A. Flight model: stall, flare, damage glide

Everything here lives in `Assets/_Project/Scripts/Flight/PlaneController.cs` (`UpdateSpeed`, `UpdateRotation`,
`UpdateVelocity`) and `Flight/PartFlightEffects.cs`. Do these together; they share `_stallLift`, `_damageLift` and
`_sinkSpeed`.

- [x] **A1. Stall at any height.** Today the stall is purely speed-based (`_stallLift = (Speed / stallSpeed)²`) and
  idle settles *just under* stall speed, so a stall mostly happens low and slow on approach. Wanted: pull the nose
  up at any altitude, bleed speed, and the plane actually stalls — nose drops, a short wing-drop/buffet, recover by
  diving for speed. Plan: add an angle-of-attack term (nose vs. `_path`) so a hard pull at cruise can break the
  wing, a stall state (`IsStalled`) with hysteresis, a buffet/wing-drop while stalled, and HUD/audio cues.
  Done: a test that climbs at full pull from 1500 m and asserts the stall triggers and recovers; bots
  (`Bots/BotSteering.cs`) avoid it.
- [x] **A2. Landing flare feels real.** Flare drag exists (`flareDrag`, `FlareSpeedFactor`, `FlareFullAngle`) but
  the user wants the round-out to *float* then settle: ground effect cushion in the last few metres, sink rate
  arrested by the flare, speed bleeding off, then the mains touch. Tie into `LandingGear` / `LandingRules`
  touchdown limits. Done: a scripted approach at `BotPilot` approach speed touches down under the sink limit
  without the pilot needing perfect timing.
- [x] **A3. No flying without wings.** `bothWingsLift = 0` already zeroes lift, but `damageSinkSpeed` gives a
  "steady sink the pilot can fly against". Wanted: one wing gone = hard spiral that's barely survivable, both wings
  gone = it falls (ballistic, no pitch authority). Done: a test that removes both wings and asserts the plane
  can't hold altitude at any throttle.
- [x] **A4. Engine loss glides.** Engine lost sets `Thrust ×0`, and `target` speed becomes 0, so the plane slows
  and drops. Wanted: a real glide — nose-down trades height for speed at a glide ratio, so a pilot can stretch to a
  runway. Plan: when thrust is 0, target speed comes from pitch (best-glide speed at a gentle nose-down),
  `glideDeceleration` only above that. Done: dead-engine test holds near best-glide speed and descends at a
  fixed ratio.
- [x] **A5. Lost elevators trend to the ground.** `hStabPitchRate = 0` + `hStabPitchStability = 0` freezes pitch
  where it was. Wanted: nose tucks down steadily (add a nose-down `PitchBias` / extra `noseDropRate`), so losing
  the elevator is a slow death dive.
- [x] **A6. Bug — lost elevators fly out of the map forever.** Same root cause: pitch frozen and nothing can turn
  the plane back. Fix with A5, *and* make sure `World/FlightBoundary.cs` still turns/kills a plane with no pitch
  control (the boundary push may rely on pitch input). Done: a test that removes the H-stab heading out and asserts
  the plane ends up crashed or back inside within N seconds.

## B. Controls and input

- [x] **B1. Touch controls don't turn off when a controller connects.** `UI/TouchControlsUI.cs` hides them only
  when `HasRealGamepad()` (checks `pad.native`) and only in `Auto` mode. Investigate on device: Bluetooth pad's
  `native` flag, the setting stuck on `ON`, and `PlayerFlightInput.TouchControlsActive` still reading touch. Also
  hide on first gamepad input, not just on connect. Done: plugging/pairing a pad mid-match hides the overlay and
  unplugging brings it back.
- [x] **B2. Phone throttle on the right hand.** Move throttle buttons/slider to the right side of the touch layout

- [x] **B3. Control remapping (at least speed up / down).** `Input/InputBindings.cs` holds bindings. Add a

- [x] **B4. Lock on only to the opposite team.** `PlaneMissiles.FindLockCandidate` loops every live plane with no

  an enemy. Done: a test with a teammate dead ahead gets no lock.

## C. Match modes and flow

- [x] **C1. Ram Royale: watch the match, then the leaderboard.** When out of lives the player spectates
  (`MatchManager.IsSpectating`, `UI/MatchScreens.cs DrawSpectating`). Wanted: keep spectating to the last plane,
  *then* show the leaderboard with a Main Menu button (no early cut to the results screen).
- [x] **C2. A crash must not open the pause menu.** `SetPicker` already clears `MenuOpen` on respawn, but the
  report says it still happens — likely the out-of-lives/spectating path (picker is `None`, so the guard in
  `OpenMenu` doesn't apply) or the gamepad-disconnect/app-pause hooks firing on crash rumble/vibration. Reproduce in
  Ram Royale first. Done: crash in every mode shows only the plane select or spectate view.
- [x] **C3. No abilities or boost in Ram Royale.** `Match/MatchMode.cs` gives Ram Royale a `RamBoostAbility`.
  Remove it and block boost (`IsBoosting`) under that mode's rules; hide the ability/boost HUD and touch buttons.
- [x] **C4. Throttle can't win back the flag-carrier slowdown.** `BannerDrag` multiplies `MaxSpeed` by 0.75, but
  `ThrottleCurve.AirSpeed` + dive (`gravityInfluence`) and boost-style throttle still reach the old speed. Clamp the
  final `Speed` to the carrier cap (dive gain included) while carrying. Done: `BannerDragTests` asserts full
  throttle never exceeds the cap.
- [x] **C5. Spawn just off the runway.** `Flight/PlaneRespawner.cs` runway spawns use takeoff slots on the strip.
  Move slots to a parking apron / taxi pad beside the runway (per `World/Airfield.cs`), facing the taxiway, so
  planes don't sit on the active runway. Rebuild map scenes after.
